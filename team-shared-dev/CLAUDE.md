## 절대 규칙
- push는 하지 않는다(사람이 한다). 병합은 검증을 통과한 작업만 하고 `main`/`master`에는 사용자가 지시할 때만
  반영한다. 패키지를 설치하지 않는다.
- `.env`, 키 파일을 읽거나 출력하지 않는다. 소스·내부 정보를 외부로 보내지 않는다.
- 테스트나 검증 기준을 삭제·완화·건너뛰지 않는다. 처리 못 하는 경우는 사유와 함께 보고한다.
- 권한 분류기 장애가 나면 우회하지 말고 보고하고 멈춘다.
- 보고할 때 [확인] / [분석] / [미확인] / [제안]을 구분한다.

## 팀 구조 (Agent Teams, 작업 폴더 공유)
| 에이전트 | 역할 |
|---|---|
| `lead` | 작업 분할·배정·커밋. 직접 구현하지 않는다. `claude --agent lead`로 실행 |
| `developer` | 담당 파일만 구현·테스트. 커밋하지 않는다 |
| `reviewer` | 읽기 전용 검토. reviewer끼리 반박·확인 |

## Hook이 강제하는 것
- 작업 생성(TaskCreated): 설명에 `담당 파일:`과 `완료 기준:`이 있어야 하고, 담당 파일이 열린 다른 작업과 겹치면 거부한다.
- 작업 완료(TaskCompleted): `verify.py`가 PASS/SKIP이어야 완료된다. 실패하면 완료가 막힌다.
- 권한: push·PR 생성 거부, merge·rebase·`reset --hard`·브랜치 삭제는 승인 없이 허용(자동 루프용).
