# deep 설계 점검표

deep 깊이에서 작업에 해당하는 절만 쓴다. 해당하지 않으면 "해당 없음: 이유" 한 줄.

## 요구사항 추적
- 기능·비기능 요구, 기존 시스템의 계약, 도메인 불변 조건, 사용자 결정, 범위 밖
- 주요 요구사항마다 어느 설계 요소와 어느 테스트로 확인하는지

## 대안 비교
- 비교 축: 구현·설계 복잡도, 안정성, 유지보수, 이식성, 보안, 장애 격리, 테스트 가능성, 기존 호환, 변경 비용, 외부 종속
- 채택 이유와 기각 이유. 측정하지 않은 값은 "미측정"

## 상태와 흐름
- 상태 전이 표(허용·금지 전이), 이벤트 순서, 종료 조건, 결정론이 필요한 범위
- 순서가 뒤바뀐 입력·중복 입력의 처리, 시간·공간 복잡도

## 동시성·트랜잭션
- 공유 상태, 잠금 범위, 원자성, 트랜잭션 경계, 경쟁 상태, 중복 요청, 교착 가능성
- 실패 뒤 다시 실행해도 불변 조건이 유지되는가(멱등성, 부분 성공)

## 장애·복구
- 잘못된 입력, 파일 손상, 외부 서비스 실패, 타임아웃, 강제 종료, 부분 기록, 버전 불일치
- 재시도·백오프·롤백·보상, 지원하지 않는 복구는 "지원 안 함"으로 명시

## 보안
- 신뢰 경계, 인증·인가, 최소 권한, 입력 검증, 파일·경로 접근, 비밀 정보, 안전한 기본값, 실패 시 권한
- 잘못 쓰기 쉬운 API가 없는가. 규칙을 문서가 아니라 코드로 강제할 방법

## 데이터
- 스키마, 필드 뜻·타입·단위·범위, NULL·빈 값의 뜻, 식별자, 참조 무결성, 인덱스
- 생명주기, 직렬화, 버전, 마이그레이션, 손실 방지, 삭제 정책

## 비기능
- 성능·지연·메모리 목표와 측정 방법, 플랫폼 호환, 관측(로그·지표)

## 호환성·마이그레이션
- 깨지는 API·데이터·설정, 단계적 전환, 롤백 가능성. 깨지는 변경은 manager를 거쳐 사용자 결정

## 검증 전략
- 정상, 경계값, 잘못된 입력, 상태 전이, 불변 조건, 오류·복구, 동시성, 하위 호환, 통합·회귀
- 입력 범위 전체에 성립해야 하는 성질은 속성 기반 테스트 후보로 적는다(이미 쓸 수 있는 라이브러리만)
