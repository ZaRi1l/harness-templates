# manager 절차 (가끔 쓰는 것)
`sched`·`integrate`는 manager.md와 같다.

## 막힘
같은 오류가 두 번 나거나, 작업이 BLOCKED가 되거나, 팀원이 도구·권한 거부로 멈췄을 때.
1. 우회하지 않는다. 다른 도구·경로로 같은 일을 시키지 않고, 설정·테스트를 바꾸지 않는다.
2. researcher에게 **막힘 진단**을 맡긴다(작업 ID `<원래 ID>-BLOCK` 같은 조사 작업, 읽기 전용). 오류 원문, 실행한 명령, 지시문을 넘긴다.
   researcher가 원인을 셋 중 하나로 나눠 근거와 함께 보고한다: 하네스·도구(지침끼리 충돌, 프로그램 거부, worktree 밖 쓰기 거부) / 환경(설치·PATH·포트·권한) / 코드.
   조사·설계 결과가 파일 없이 메시지로만 오면(e2e6), 그 작업을 block하지 않는다. 우회가 아니다: 보고 원문을 `start`의 `output` 경로
   (없으면 `docs/asterbraid/research/<시각>-<ID>.md`, 설계면 `design/`)에 그대로 옮겨 쓰고 첫머리에 "작성: <역할>(manager가 옮김)"을 적은 뒤
   `done ID --close --notes 경로`로 닫는다. 다음 지시문에는 "산출물: <경로>"를 확정 경로로 쓴다("가능하면"처럼 선택으로 쓰지 않는다).
3. 하네스·도구 문제: 사용자 결정을 열지 않는다. 하네스가 허락하는 다른 방법이 있으면 그 방법으로 다시 지시한다
   (예: 임시 파일은 `sched notes-dir ID`가 준 폴더). 없으면 그 작업만 `sched block ID --reason …`, `sched note --kind blocker`에 원인을 적고
   다른 작업을 계속한다. 끝 보고의 "하네스 문제"에 적는다.
4. 코드 문제: 같은 implementer에게 원인과 함께 재작업을 시킨다(`fail` → `start`).
5. 환경 문제: 사용자만 풀 수 있으면 결정 하나(`--kind environment`)로 연다.
   (a) 환경을 고치고 재시험 (b) 승인받아 그 테스트를 환경 의존으로 표시(같은 동작은 환경에 기대지 않는 테스트로 지키고 결정 ID를 커밋에) (c) 보류.
   풀리면 `sched unblock ID`.

## 끝·중간 인계
- **끝**: 남은 작업이 모두 COMPLETED·BLOCKED·CANCELLED.
- **중간 인계**: 남은 일이 사용자 답(결정·승인)뿐이고 더 배정할 것이 없다. 기다리며 조회를 되풀이하지 않는다.
1. `sched cleanup --dry-run`, 이어서 `sched cleanup`(끝난 작업의 worktree·브랜치만 지운다). 거부되면 사유(남은 파일·프로세스)를 확인하고, 우회하지 말고 목록을 보고에 넣는다.
2. 세션에서 띄운 서버·브라우저가 남았는지 확인하고 끈다. 자기가 만든 `.playwright-cli/`는 지운다.
3. `sched metrics`를 실행한다.
4. `docs/asterbraid/reports/YYYY-MM-DD-HHMM-<주제>.md`에 보고를 쓴다: 작업별 결과, 통합 커밋, 보류·남은 일과 이유, 사용자가 답할 결정·승인,
   자리 비움 중 자동으로 정한 것, 하네스 문제, 지표(명령 출력에서 옮긴다). 요구 문서 상태·INDEX를 고치고 그 파일들만 경로로 커밋한다.
5. 대화에 보고 요약과 "사용자가 할 일"(답할 결정, `main` 반영 등)을 적는다. push·`main` 반영은 하지 않는다.
