# 설계 기록

## 결정
| 주제 | 결정 | 이유 |
|---|---|---|
| 상태 저장 | JSON 파일 + 잠금 파일 + 원자적 교체 | 에이전트와 사람이 바로 읽는다. 표준 라이브러리만으로 Windows·Linux에서 같다. SQLite는 동시성은 낫지만 열어 보기 어렵다 |
| 저장 위치 | `.git/claude-auto/` (공통 git 폴더) | 모든 worktree가 같은 상태를 본다. 작업 폴더를 더럽히지 않아 통합이 막히지 않는다 |
| 상태 변경 | `sched.py` 명령으로만 | 전이·의존성·경로·슬롯 규칙을 한곳에서 강제한다. 임의 전이 명령은 두지 않았다 |
| Integrator | 에이전트가 아니라 `integrate.py` | 병합은 판단이 아니라 절차다. 프로그램이 더 안전하고 싸다 |
| 통합 방식 | 임시 worktree에서 병합·전체 테스트 → 통합 브랜치에 `merge --ff-only` | 통합 브랜치는 검증된 결과로만 움직인다. ff는 ref와 체크아웃을 함께 옮긴다 |
| 검증 증거 | 커밋 SHA + 검증 기준 버전에 묶음 | 기준 버전 = `verify.py`·`verify.config.json`·완료 기준·승인된 미리보기의 해시. 하나라도 바뀌면 무효 |
| 충돌 해결 | implementer가 `sched sync`로 통합 브랜치를 가져와 직접 푼다 | 충돌은 판단이 필요하다. 프로그램은 병합만 대신 실행해 직접 `git merge` 권한이 필요 없게 한다 |
| 권한 | 프로그램 호출은 허용, 직접 하는 merge·rebase·reset·삭제와 `.claude/` 수정은 승인 필요 | 자동 루프는 프로그램만으로 돈다. 게이트를 우회하는 명령은 사람이 본다 |
| 미리보기 승인 | 작업의 사전 단계로 넣고 승인은 CLI로 기록 | 승인 대기가 그 작업만 막는다. 로컬 서버는 두지 않았다(공격면·의존성) |
| 병렬도 | 풀별 슬롯 한도, 수동 조절 | 실행 환경의 자원·토큰 정보를 프로그램이 얻을 수 없어 자동 조절은 넣지 않았다 |
| 조사·설계 산출물 | 작업별 노트 폴더(`.git/claude-auto/notes/<ID>/`) | 중간 산출물이 통합 브랜치를 더럽히지 않고 서로 겹치지 않는다. 정식 문서는 일반 작업으로 만든다 |

## 무엇이 어떻게 보장되나
| 항목 | 방식 |
|---|---|
| 상태 전이, 의존성 순환, 중복 배정, 경로 충돌, 슬롯 한도, 재시도 한도 | 프로그램 + 테스트 |
| 담당 경로 밖 변경 제출 거부 | 프로그램 + 테스트 |
| 검증 안 된·검증 뒤 바뀐 커밋 병합 거부, 증거·보고서 누락 거부 | 프로그램 + 테스트 |
| 충돌·통합 테스트 실패·강제 종료 시 통합 브랜치 불변 | 프로그램 + 테스트 |
| 동시 통합 거부, 재실행 멱등성, 중단 복구, 안전한 정리 | 프로그램 + 테스트 |
| 미리보기 승인 전 구현 시작 거부, 버전 보존 | 프로그램 + 테스트 |
| 작업 분할·프로파일 선택의 질, verifier 판단의 질 | 지침 |
| manager·verifier가 제품 코드를 고치지 않는다 | 지침 (verifier는 Edit·Write 도구 없음, Bash는 가능) |
| 병렬로 실제 띄우기, 빈 슬롯 채우기 | 지침 (프로그램은 무엇을 띄울 수 있는지만 알려 준다) |
| 사용자에게 묻는 기준 | 지침 |
| 직접 하는 git 명령 차단 | 설정(문자열 비교). 샌드박스가 아니다 |

## 넣지 않은 것
- 로컬 승인 서버, 토큰·비용 수집, 자동 병렬도 조절, 조사 결과의 자동 만료 판단.
- 실제 Claude Code 세션 E2E. 프로그램 테스트만 했다.
